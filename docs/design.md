# Herdr Hub — 설계와 기능

무엇이 어디 있는지의 정본이다(처음 보는 사람용 소개는 [README](../README.md), 여러 호스트·설정·운영은 [operations.md](operations.md)).

예전 이름은 Paddock 이었다. 저장소·폴더(`herdr-hub`)·예약 작업(`HerdrHub`)·LaunchAgent(`local.herdr-hub`)·헤더(`X-Herdr-Hub`)·환경 변수(`HERDR_HUB_*`)까지 모두 바꿨다. 예전 `paddock-uploads` 사진과 브라우저 설정(`paddock.*`)은 처음 실행할 때 새 이름으로 옮긴다.

herdr 에이전트를 휴대폰에서 보고 답하는 웹앱(PWA). herdr가 도는 호스트에서 돌고, Tailscale 로만 접속한다.

설치하면 전체 화면(`display: fullscreen`)으로 열린다: Android 는 위 상태바와 아래 내비게이션 바·작업 표시줄을 숨기고, 화면 가장자리를 쓸면 잠깐 나온다(iOS 는 이 값을 standalone 으로 받는다). 이미 설치한 앱은 Chrome 이 매니페스트 변경을 늦게 반영하므로, 바로 바꾸려면 지우고 다시 설치한다. 알림 안내의 「설치된 앱인가」는 standalone·fullscreen 둘 다 본다.

- 서버: herdr API 소켓(Windows 는 named pipe)에 직접 붙는다. SSH·셸을 거치지 않는다. 시작 명령은 어디서나 `node server.js` 다.
  - `server.js` 는 프로세스만 맡는다(스레드 수, 설정이 틀리면 끝내기, 감시 스레드, 사진 청소, 듣기, 신호). 허브 자체는 `lib/hub.js` 의 `createServer({ herdr, env, dataDir, port, peers, now })`: 상태·herdr 에서 새로 읽기(refresh)·알림·피어·HTTP 서버·실시간 연결을 만들고, 경로들이 쓰는 것을 `hub` 객체 하나로 넘긴다. 시험은 이것을 같은 프로세스에서 가짜 herdr 로 띄울 수 있다(`test/fixtures/hub.js` hubInProcess; `node server.js` 를 띄우는 startHub 도 있다).
  - API 경로는 표 하나다(`lib/routes/index.js`, 맞추기는 `lib/router.js`): `[방법, 모양, 할 일]` 줄을 차례로 보고 처음 맞는 줄이 답한다. 모양은 `/api` 뒤의 조각들 — 글자 그대로, `:이름`(아무 조각), 끝의 `*`(뒤에 더 있어도 없어도). 앞 줄이 확인만 하고(그 에이전트가 있는가, 본문 읽기) `NEXT` 를 돌려주면 다음 줄이 이어 받는다. 영역별 파일: `state`(상태·버전·스트림·호스트·폴더 찾아보기) `peers`(`/peers/<호스트>/…` 피어로 넘기기, `/hosts` 설정 → 연결) `workspaces` `panes` `agents`(답하기와 알림 단추의 `/answer` 포함) `uploads` `push`. 실시간 연결(WebSocket)은 `lib/routes/live.js`, 셸 패널에 키 보내기·화면 읽기·herdr 깨워 두기는 `lib/paneio.js`. 새 경로는 그 영역 파일에 한 줄을 더하고, 경로·상태 코드·본문을 바꾸지 않는 한 `API_VERSION` 은 그대로다.
  - 경로 시험(`npm test`): `test/answer.test.js`(답: 거절은 키를 하나도 안 보낸다, 동시에 둘이면 하나만, 5 초 안 두 번째 거절, Type something, 보내기 실패 뒤 다시, herdr 가 idle 로 바꾼 계획 질문), `test/dialog.test.js`(herdr 가 idle 로 둔 선택 창: 답 필요, 글은 막고 아무 키도 안 보냄), `test/routes.test.js`(prompt·키·닫기·이름·라우터의 404/400/405), `test/proxy.test.js`(서버 둘: 그 피어에만 닿기, 넘기지 않는 경로, 꺼진 피어의 503 과 마지막 대화, `/api/answer` 넘기기, 실시간 연결 다리), `test/hub.test.js`(같은 프로세스, 시계를 옮겨 5 초 홀드).
- 화면: `public/` — 빌드 없는 바닐라 JS. 목록, 에이전트 보기(대화 + 작업 줄 + 터미널 화면 시트), 응답 키, 보내기, 중단(Esc), 웹 푸시 알림.
  - 말(`public/i18n.js`, `i18n.en.js`): 한국어·영어. 설정 → 화면 → 「언어 · Language」(기기 따라 / 한국어 / English, `herdr-hub.lang`)를 `index.html` 이 스크립트보다 먼저 읽어 `<html lang>` 을 정하고, 페이지는 그동안 그 언어다(바꾸면 다시 연다). 영어가 생기기 전부터 쓰던 기기(설정이 이미 있는)는 한국어로 남고, 새로 연 기기는 브라우저 언어를 따른다. 한국어 문구가 키라 영어가 빠진 곳은 한국어로 보인다. 알림은 구독할 때 그 기기의 언어를 함께 저장해(`lib/push.js`, 상태를 물을 때 다르면 다시 보낸다) 그 언어로 만들고(`lib/notify.js` buildPayload lang, 언어마다 한 번), 알림에서 답한 뒤의 확인 문구는 서비스 워커가 그 알림의 언어로 쓴다(`sw.js`). 오프라인 페이지도 같은 파일을 읽는다.
  - 파일: 번들러 없이 `index.html` 이 `<script defer>` 로 차례대로 읽고, 모두 한 전역 범위를 나눠 쓴다. 먼저 순수 함수 파일(`choices` `ansi` `activity` `mode` `inbox` `rowtext` `statepatch` `split` `keys` `predict` `keymap` `prefs` `route` `markdown` `update` `conn` `motion` `forward` `quick` `slash`, 시험은 `npm test`), 그다음 `core.js`(상태·api()·설정값 이름·시트·메뉴·단축키 시트·알림 줄), 화면별 파일 `list` `rows` `tabswipe` `backswipe` `fwdchip` `answer` `chat` `composer` `agent` `actions` `shell` `screen` `workspace` `forms` `switcher` `push` `settings` `keyspage` `viewport`, 맨 끝에 `app.js`(실시간 연결·주소·두 칸 배치·시작). 맨 위 코드는 리스너 등록과 정의만 하고, 그리는 일은 `app.js` 에서 시작한다. 새 파일은 `index.html` 에 `?v=` 없이 그냥 넣는다(서버가 붙인다, 아래 정적 파일).
  - 서버 쪽 도움 모듈: `lib/http.js`(응답·본문·정적 파일·Host 검사), `lib/tools.js`(도구 한 줄 요약), `lib/validate.js`(키·글·이름·폴더·에이전트 검사), `lib/screen.js`(패널 읽기와 herdr 대체 경로), `lib/fsq.js`(요청 길의 파일 읽기: 비동기·시간 예산·막힌 경로 건너뛰기), `lib/watchdog.js`(멈춘 프로세스를 죽이는 감시 스레드).
- 탭: 아래 탭 막대 「작업공간 / 설정」(`#/`, `#/settings`). 앱은 작업공간으로 열린다. 예전 홈 탭은 없앴다: 예전 주소 `#/spaces`(`#/h/<host>/spaces`)는 `#/` 로 바뀌고, 마지막 탭을 적어 두던 `herdr-hub.tab` 은 처음 열 때 지운다. 에이전트·셸·워크스페이스 화면의 뒤로는 작업공간으로 간다. 목록의 스크롤 위치를 기억한다. 호스트 선택·+ 는 작업공간 머리글에 있다. 작업공간 카드 맨 위의 이름을 누르면 그 워크스페이스 화면(`#/ws/<id>`, 두 칸이면 오른쪽)이 열리고, 옆의 ⋯ 는 그 메뉴다. 작업공간 탭에는 답 필요 수가 뜬다.
- 넓은 화면(폭 1000px 이상: 가로로 둔 Galaxy Tab S7+, 노트북)은 두 칸이다(`public/split.js`, 시험은 `npm test`). 맨 왼쪽은 VS Code 처럼 활동 막대(52px: 위에 작업공간, 아래 끝에 설정), 그 옆 사이드바는 늘 작업공간 목록과 호스트 선택·+, 오른쪽은 연 에이전트·셸·워크스페이스·새 워크스페이스·설정 화면. 아무것도 열지 않았으면 「왼쪽에서 에이전트를 고르세요」와 이 기기의 단축키 세 가지(빠른 이동·목록 옮기기·모든 단축키; 나머지는 단축키 페이지에. 키와 설명 한 묶음은 줄에서 갈라지지 않는다). 접혀 있으면 「목록 펴기」와 「작업공간 목록 열기」(Ctrl+B 툴팁). 워크스페이스가 하나도 없으면 오른쪽이 「아직 워크스페이스가 없습니다」와 큰 「새 워크스페이스」 단추를 보이고(왼쪽은 짧은 한 줄), herdr·피어에 닿지 못하면 그 까닭과 「연결 상태 보기」. 세로 태블릿(876)·화면 분할의 반쪽·휴대폰은 전과 같은 한 칸이다.
  - 두 칸의 대화 화면은 한 열이다: 머리글 안쪽(제목·배지·⋯·✕), 작업 줄, 메시지와 「↓ 최신 대화」 알약, 답 필요 상자, 사진 미리보기, 명령 제안, 입력 칸이 모두 같은 왼쪽·오른쪽 선을 쓴다. 가로줄과 바탕만 칸 끝까지 간다. 열 폭은 설정 → 화면 → 「대화 폭」(`herdr-hub.chatW`)을 따른다: 자동(기본)은 칸 폭에서 양옆 24px 씩(목록·설정 카드·시트의 16–24px 와 같은 여백)을 뺀 폭을 760–1680px 안에서 쓰고(1512 노트북의 두 칸은 약 1080px, 2560 모니터는 1680px), 좁게는 760px, 넓게는 양옆 16px 씩만 빼고 최대 2400px, 꽉 차게는 칸 전체. 대화 글자도 화면 폭에 따라 16px(노트북)에서 18px(큰 모니터)까지 조금씩 커진다(코드는 13–15px). 대답의 표와 코드 블록도 글과 같은 왼쪽·오른쪽 선을 쓴다: 열 밖으로 나가지 않는다(넓은 표는 그 안에서 옆으로 민다; `style.css` `.detail.chat` 의 `--col`·`--gut`, 칸 폭에서 셈한다). 휴대폰은 그대로다.
  - 사이드바 폭: 마우스 기기는 `clamp(288px, 22vw, 340px)`(1280 에서 288, 1440 에서 317), 터치 기기는 `clamp(320px, 27vw, 360px)`, 어느 쪽이든 화면의 45% 를 넘지 않는다(`style.css` `--list-w`). 호스트 칸(전체·기기) 단추는 터치 기기에서 44px, 마우스 기기에서는 32px 다. 사이드바 안쪽 여백은 휴대폰보다 좁고(제목·호스트 칸·카드가 모두 왼쪽 8px 한 선, 줄 왼쪽 16px, 아이콘 24px), 상태는 색 글자(답 필요만 알약)라 제목에 폭이 더 간다. 사이드바 오른쪽 가장자리(`.list-grip`, `role=separator`)를 끌면 240–480px 로 바뀌고, 두 번 누르면 자동으로 돌아간다. 가장자리에 포커스가 있으면 ←/→ 로 16px 씩, Home/End, 리턴은 자동. 설정 → 화면 → 목록 칸 폭(자동·좁게 264·넓게 400, 끌어서 맞춘 값은 그 px; `prefs.js` listW, `herdr-hub.listW`)과 같은 값이다.
  - 머리글 높이: 두 칸 화면의 모든 머리글(목록·대화·셸·워크스페이스·새 워크스페이스·에이전트 시작·설정·단축키)은 `--bar-h`(58px) 로 높이가 같아, 머리글 아래 선이 레일(같은 높이에 선을 긋는다)부터 오른쪽 끝까지 한 줄이다. 그래서 두 칸 화면의 머리글은 제목 한 줄 + 부제 한 줄까지다(두 줄 제목은 휴대폰만). 확인: 두 칸 화면에서 `[...document.querySelectorAll('.bar')].map(e => e.getBoundingClientRect().bottom)` 이 모두 같은지 본다.
  - 칸 옮기기: F6 / Shift+F6(VS Code 처럼) 이 포커스를 레일 → 목록(고른 줄) → 오른쪽(입력 칸, 없으면 그 페이지)으로 돌린다. 입력 칸과 셸 화면에서도 된다(셸에서 F6 을 가져간다).
  - 끊긴 동안: 실시간 연결이 끊기면 목록 카드가 흐려지고 시간이 멈춘다(머리글의 「연결 끊김」 칩이 까닭).
  - 주소가 정본이다: 에이전트 주소는 왼쪽 목록 + 오른쪽 에이전트로 그린다. 줄을 누르면 왼쪽은 다시 그리지 않고(스크롤 그대로) 오른쪽만 바뀌며, 연 줄은 `aria-current` 로 표시한다. 오른쪽 머리글의 뒤로는 끝의 ✕(닫기)가 되고 목록 주소로 간다. Esc 도 닫는다(셸 화면은 빼고: 거기서 Esc 는 셸로 간다).
  - 활동 막대: 두 칸 화면에서는 아래 탭 막대 대신 이것이다. 작업공간 아이콘은 사이드바를 접고 편다: 펴져 있으면 표시되고(`aria-pressed`, 막대 가장자리 줄) 답 필요 수가 뜬다. 접으면 오른쪽이 그 폭까지 넓어진다(셸 화면도 그만큼 넓어진다). 접힘은 이 기기에 기억한다(`herdr-hub.sideOff`). 설정 아이콘은 VS Code 처럼 설정을 사이드바가 아니라 오른쪽에 연다(`#/settings`, 열려 있으면 표시된다). 사이드바는 그대로 작업공간 목록이다. 설정의 ✕·Esc·설정 아이콘을 다시 누르면 설정을 열기 전 오른쪽에 있던 에이전트·셸·워크스페이스로 돌아가고(없었으면 빈 화면), 목록의 줄을 누르면 그쪽으로 바뀐다. 사이드바가 접혀 있어도 설정은 펴지 않고 오른쪽에 연다. 키보드로는 Ctrl+B 와 Alt+B 가 작업공간 아이콘과 같다(메시지 칸에서도 된다). 셸 화면에서는 Ctrl+B 가 셸 키라 셸로 가고 Alt+B 만 사이드바다(셸의 한 단어 뒤로는 Alt+← 로; 키 줄의 Alt 로는 셸에 alt+b 를 보낸다).
  - 접힌 동안: 안 읽은 끝남이 작업공간 아이콘의 점으로 보인다(답 필요가 있으면 수가 대신 뜬다). Alt+↑/↓ 는 접힌 목록에서도 그대로 움직인다(설정이 열려 있으면 그 자리에 다음 줄을 연다). 아무것도 열지 않았으면 오른쪽에 「목록을 열어 에이전트를 고르세요」와 「작업공간 목록 열기」.
  - 무언가 열린 동안 활동 막대의 다른 탭을 누르면 사이드바만 바뀌고 오른쪽은 그대로다. 열린 것이 없으면 그 탭 주소로 간다.
  - 단축키는 모두 `public/keymap.js` 의 표 하나에 있고(`app.js` 의 `KEY_ACTIONS` 가 실행), 단축키 페이지(Ctrl+? 곧 Ctrl+Shift+/, 설정 → 단축키)가 그 표를 그대로 보여 준다. 새 단축키를 넣는 규칙은 `AGENTS.md`. 아래는 각 키의 자세한 동작이다.

  - 대화창 닫기(설치한 앱에서 Ctrl+W, Mac ⌘W): ‹(✕)처럼 연 에이전트·셸·워크스페이스에서 나온다. 에이전트는 그대로 돈다. 입력 칸에서도 되고, 시트·메뉴가 열려 있으면 그것을 닫고, 설정이면 설정을 닫는다. 닫을 것이 없으면(목록만 있을 때) 키를 브라우저에 맡겨 앱 창이 닫힌다(다른 앱에서 ⌘W 가 창을 닫는 것처럼). 키를 누르고 있어도 하나만 닫고 창까지 닫지는 않는다. 셸 화면에서 Ctrl+W 는 셸의 한 단어 지우기라 셸로 가고(Mac 의 ⌘W 는 셸 화면에서도 대화창 닫기), 셸의 한 줄 입력 칸에서는 커서 앞 단어를 지운다(셸의 Ctrl+W 처럼; 예전에는 브라우저로 가 앱 창이 닫혔다).
  - 키보드: `/` 는 입력 칸, Alt+↑/↓(vim 처럼 Alt+K/J 도) 는 왼쪽 목록의 이전·다음 에이전트(셸 포함)를 오른쪽에 연다(입력 칸에서도, 셸에서도 된다; 셸의 Alt+K/J 는 셸로 보내지 않는다, 키 줄의 붙는 Alt 로는 간다; 단축키 페이지의 「셸」 스위치로 바꿀 수 있다). Ctrl+, 는 설정을 열고 닫는다(VS Code 처럼; 입력 칸에서도, 셸 화면에서는 안 된다). Alt+↑/↓ 로 옮기면 연 쪽의 입력 칸에 포커스가 간다. 워크스페이스 화면이 열려 있으면 그 카드에서 옮긴다: ↓ 는 그 카드의 첫 줄, ↑ 는 앞 카드의 마지막 줄(`split.js` stepRow 의 heads). 키로 새 워크스페이스를 열면 포커스가 양식의 첫 칸(호스트, 없으면 폴더 찾아보기)으로 가고, 연 동안 목록 머리글의 + 가 표시된다. 레일의 설정 단추에도 Ctrl+, 툴팁이 있다. 셸 화면에서는 Alt+↑/↓ 만 목록 키다: Esc·`[`·`]`·`/` 와 다른 키는 포커스가 어디 있든(화면, 키 줄, 방금 누른 목록 줄) 셸로 간다(아래 「셸 화면의 키보드」). 셸에서 나가는 길은 ‹(✕)와 Alt+↑/↓.
  - 그 밖의 키: Alt+Shift+↓/↑ 는 목록 순서로 다음·이전 답 필요 에이전트를 연다(끝에서 처음으로 돌고, 없으면 알림 줄; 입력 칸·셸 화면에서도). Alt+T 는 대화 화면에서 터미널 화면 시트를 열고 닫는다(셸 화면에서는 셸의 키). Alt+` 는 직전에 보던 에이전트·셸로 가고, 다시 누르면 돌아온다(설정·폼을 거쳐도 그 둘만 기억한다). 목록·설정에서는 방금 나온 것(마지막에 연 것)을 다시 연다: 「방금 본 대화」 칩과 같다. 셋 다 옮긴 뒤 입력 칸에 포커스를 준다(Alt+T 는 빼고).
  - Alt+M: ⋯ 메뉴. 목록(또는 워크스페이스 화면의 줄)에 포커스가 있으면 그 줄의 메뉴, 아니면 연 에이전트·셸·워크스페이스의 메뉴. 셸 화면에서는 Alt+M 이 셸의 키라 Ctrl+Alt+M(Hub 는 Ctrl+Alt 조합을 셸로 보내지 않는다). 메뉴 안에서는 ↑↓(Ctrl+J/K 도, 끝에서 처음으로 돈다)·Home·End 로 옮긴다.
  - Alt+W: 연 에이전트·셸을 끝낸다(워크스페이스 화면이면 그 워크스페이스를 닫는다; 「끝내기」). 키 하나로 끝나지 않게 ⋯ 메뉴의 「에이전트 끝내기」·「셸 끝내기」와 같은 확인 창을 띄운다. 말은 하나로 맞춘다: 에이전트·셸은 「끝내기」(확인 창의 단추, ⋯ 메뉴, 단축키 페이지, 알림 「에이전트를 끝냈습니다」), 워크스페이스는 「워크스페이스 닫기」, 그냥 「닫기」는 화면에서 나오는 대화창 닫기(Ctrl+W·⌘W)다. 되돌릴 수 없는 확인 창(끝내기, 워크스페이스 닫기, 중단, 호스트 빼기, 저장 데이터 지우기; `sheet({ danger })`)은 「취소」에 포커스를 두어 습관처럼 친 리턴은 그만두기가 되고, Ctrl+리턴(⌘+리턴)이나 그 창을 연 키 한 번 더(Alt+W, Alt+Shift+W)로 확인한다. Esc 도 그만둔다. 그 키들은 따로 한 줄로 적지 않고 확인 단추의 툴팁(「확인: Alt+W 또는 ⌘+리턴」)과 `aria-keyshortcuts` 에, 키보드가 있을 때만 단추 안의 흐린 키 하나(그 창을 연 키)로 보인다. 다만 이 기기(이 탭)에서 시작하고 아직 아무것도 보내지 않은 새 대화(Ctrl+N 을 잘못 눌렀을 때; 대화에 사용자 메시지가 없고 대기 중인 것도 없고 일하는 중도 아님, `quick.js` unused)는 묻지 않고 바로 끝내고 「새 대화를 끝냈습니다」를 띄운다(Alt+W·Ctrl+Alt+W·⋯ 의 끝내기 모두; 그 대화가 열려 있지 않아 기록을 모르면 묻는다). 저절로 끝내는 일은 없다(Mac 은 Option+W). 대화창 닫기(설치한 앱의 Ctrl+W·⌘W, 위)는 에이전트를 끝내지 않고 화면에서 나올 뿐이다. 셸 화면에서는 Alt+W 가 셸의 키라 셸로 간다. Ctrl+Alt+W 는 같은 끝내기를 셸 화면에서도 한다(그 셸을 끝내는 확인 창; Hub 는 Ctrl+Alt 조합을 셸로 보내지 않는다).
  - 워크스페이스 닫기: Alt+Shift+W(Option+Shift+W, 끝내기에 Shift 를 더한 더 큰 닫기)는 연 에이전트·셸·워크스페이스가 든 워크스페이스를, 목록(과 워크스페이스 화면의 줄)에서는 포커스가 있는 줄의 워크스페이스를 닫는다(`app.js` workspaceHere; 아무것도 없으면 아무 일도 없다). ⋯ 메뉴의 「워크스페이스 닫기」와 같은 확인 창이고 같은 키 한 번 더로 확인한다. 터미널은 Alt+Shift+W 를 Alt+W 로 받으므로 셸 화면에서는 셸로 가고, 거기서는 Ctrl+Alt+Shift+W 다(셸로 가는 키가 아니다). ⌘⇧W·Ctrl+Shift+W 는 브라우저의 창 닫기라 쓰지 않는다.
  - 확인 창의 모양(`core.js` sheet, `style.css` `.sheet.dialog`): 제목이 묻는 말에 대상 이름을 함께 쓴다(「‘hub-qtest’ 에이전트를 끝낼까요?」, 이름은 48자에서 자른다), 본문은 무엇이 끝나는지 한 줄(에이전트 「에이전트와 대화가 끝나고 되돌릴 수 없습니다.」, 셸 「셸에서 돌던 것이 끝납니다.」, 워크스페이스 「안의 에이전트 2개와 셸 1개가 모두 끝납니다.」), 단추는 「취소」·「끝내기」(「워크스페이스 닫기」). 넓은 화면에서는 폭 420px 카드에 여백 22–24px, 단추는 오른쪽에 같은 높이로; 휴대폰은 아래 시트에 두 단추가 같은 폭으로 나란하고 하는 쪽이 오른쪽, 안전 영역만큼 띄운다. 위험한 단추(`.btn.danger`, 어디서나 같다)는 붉은 판 대신 `--blocked` 글자·옅은 `--blocked-bg` 바탕·`--blocked` 테두리다(대비 밝게 4.7:1, 어둡게 7.1:1). `sheet()` 를 쓰는 모든 창(이름 바꾸기, 호스트 빼기 …)이 같은 모양이다.
  - Shift+Tab(메시지 칸에서만): 에이전트 모드를 다음 것으로 바꾼다(Claude Code 의 Shift+Tab 을 herdr 로 한 번 보낸다 — 터미널에서 하던 그대로). 머리글의 모드 칩과 명령 「에이전트 모드 바꾸기」는 고르는 메뉴를 연다(아래). 다른 곳에서는 늘 하던 대로 포커스를 뒤로 옮기고, 셸 화면에서는 셸의 키다.
  - 버튼의 단축키: 단축키가 있는 버튼은 툴팁(`title`)에 「중단 (Alt+. ×2)」처럼 키를 적는다(`core.js` keyAttrs). 글은 `keymap.js` 의 `hint(action, ctx)` 라 표와 늘 같고, 키를 바꾸면 따라간다: 그 자리에서 되는 첫 키(셸 화면에서는 셸이 아닌 Hub 가 받는 키 — 줄바꿈 Ctrl+Alt+Z, 끝내기 Ctrl+Alt+W, ⋯ Ctrl+Alt+M; 셸로 가는 키뿐이면 키를 적지 않는다). 뒤로는 「Esc · Ctrl+[」 둘 다(덮개의 Esc 는 웹에 오지 않는다). 메뉴 줄 끝의 키와 빠른 이동의 안내 줄도 같은 함수다. 모든 키는 단축키 페이지(`?`)에 있다.
  - 단축키 페이지(`#/keys`, `public/keyspage.js`): 먼저 읽기 쉬운 단축키 표, 바꾸기는 누를 때만. Ctrl+?(Ctrl+Shift+/; 입력 칸·셸 화면에서도, 다시 누르면 닫힘)나 설정 → 단축키 보기·바꾸기로 연다. 두 칸이면 설정처럼 오른쪽에, 휴대폰이면 따로 한 화면이고, ✕·뒤로·Esc 는 열기 전 화면으로 간다(휴대폰에서 설정으로 열었으면 설정). 화면마다 탭이 있다: **어디서나 · 대화 · 셸 · 목록**(`keymap.js` TABS·tabsOf). 동작은 그것이 되는 화면의 탭마다 나온다: ACTIONS 의 묶음(어디서나 / 대화·터미널 화면 / 목록)과 `also`(워크스페이스 닫기는 목록에서도), 그리고 셸 화면에서 Hub 가 쓰는 키가 하나라도 있으면 「셸」(지금 표 그대로라 스위치를 끄면 빠진다; 뒤로는 셸에서는 셸의 Esc 라 빠진다). 입력 칸·창 안의 키(LOCAL)는 그 탭의 끝에 「메시지 칸 안에서」·「빠른 이동 안에서」처럼(`localTab`), 키 없는 안내는 그 아래 글로. 연 화면에 따라 탭이 정해진다: 셸에서 열면 셸, 대화에서 열면 대화, 목록에서 열면 목록, 그 밖에는 어디서나(기억하지 않는다). 탭은 ARIA tablist 다(←/→·Home·End 로 옮긴다). 보기에서는 동작마다 한 줄: 짧은 이름(ACTIONS 의 `name`)과 이 기기의 첫 키 하나(`primaryKey`: Mac 은 ⌘, 셸 탭에서는 셸 화면에서 되는 키), 나머지 키는 「+2」로 접혀 누르면 펼친다(툴팁에도). 긴 설명(`label`)은 줄의 툴팁이고, 툴팁이 없는 터치 화면을 위해 줄을 누르면 이름 아래에 펼친다(한 번에 한 줄; 이름이 단추라 키보드로도, `aria-expanded`). 페이지가 넓으면(목록 폭 880px 이상) 두 줄로 놓는다. 「셸」 탭만 셸과 Hub 사이를 말한다: 「셸 화면에서는 이 키만 Hub 가 쓰고, 나머지 키는 모두 셸로 갑니다」. 찾기 칸은 모든 탭을 한꺼번에 찾는다(이름·설명·키 이름의 낱말, `keymap.js` search): 결과마다 그 탭 이름을 적고, 찾는 동안 탭 표시는 물러난다(탭을 누르면 찾기를 지운다). 「⌨ 키로 찾기」를 누른 뒤 키를 누르면 그 키를 쓰는 동작만 남기고, 페이지가 받은 키를 그대로(key·code·보조키) 한 줄로 보여 준다: 아무것도 안 뜨면 기기가 먼저 가져간 키다. 머리글의 「바꾸기」(누르면 「완료」)가 바꾸는 도구를 연다: 동작마다 이름 아래 긴 설명과 어디서 되는지(`whereText`: 입력 칸에서도·두 칸에서만·시트 위에서도, 키마다 다르면 「(End 빼고)」), 모든 키와 ×·+·「기본값」, 이 창의 탭·창 키 안내. 바꾸기도 그 자리에서: 키 칩의 × 로 빼고(알림 줄의 「되돌리기」로 되돌린다), 「+」를 누른 뒤 원하는 키를 누르면 더한다(Esc 나 그 자리의 「취소」로 그만둔다; 키보드 없는 폰도). 뒤로의 Esc 칩에는 × 대신 「고정」. 「셸」 탭의 스위치는 켜지면 꽉 찬 「Hub」, 꺼지면 테두리만 있는 「셸로」다(색만이 아니라 모양과 글자로 다르다). 「키로 찾기」의 안내는 본문 글꼴, 받은 값만 고정폭이고, 다른 키를 녹음하거나 끄면 지운다. 찾기 칸은 16px(iOS 가 확대하지 않게). 바꾼 동작에는 이름 옆에 작은 점(보기에서도), 바꾸기에서 「기본값」과 아래의 「모든 단축키를 기본값으로」. 바꾼 키가 있으면 「바꾼 키만」으로 그것만 본다. 이 기기에만 저장한다(`herdr-hub.keys`, 동작마다 그 키 전체). 다른 동작이 쓰던 키를 누르면 그쪽에서 옮겨 오고 알림 줄에 알린다. 받지 않는 키: 브라우저 탭에서 브라우저가 먼저 가져가는 키(Ctrl+W·Ctrl+T·Ctrl+Tab·⌘W·⌘N 등; 설치한 앱에서는 받는다), 앱을 끝내거나 시스템이 쓰는 키(⌘Q·⌘H·Alt+F4 등), Ctrl·Alt·⌘ 없는 리턴·Tab·Space·Backspace·Delete, 뒤로 말고는 Esc, 답 고르기의 1–9. 뒤로의 Esc 와 답 고르기는 바꿀 수 없다. 바꾼 키가 어디서 되는지는 그 동작의 기본 키에서 가져오되(기본 키였던 것은 기본 그대로), Ctrl·Alt·⌘ 없는 키는 입력 칸 밖에서만, 셸이 쓰는 키(`keys.js` rawKeyName)는 셸 화면에서 빼서, 글자를 치거나 셸 키를 뺏지 않는다(`keymap.js` setOverrides·assign, 시험은 `npm test`). 「셸」 탭에서 바꾸기를 켜면 셸 화면에서 쓸 만한 동작의 키 칩마다 작은 스위치가 있다(「셸 화면에서도」, `keymap.js` setShell; 지금 셸로 가는 동작은 「셸로 가는 키 (켜면 Hub 가 씀)」 아래에): 켜면 셸 화면에서도 Hub 가 그 키를 쓰고, 끄면 셸 화면에서는 셸로 간다. 처음 값은 위의 저절로 정한 값이고, 켠 키를 셸이 쓰면 그 동작 아래에 무엇을 잃는지 적는다(「Alt+B: 셸의 한 단어 뒤로(alt+b) 대신 Hub 가 씁니다」, 잘 알려진 셸 키는 `keys.js` shellMeaning, 아니면 「셸이 이 키(…)를 받지 못합니다」). 뒤로(셸에서는 셸의 Esc), 글자를 치는 키, 셸 화면에서 쓸 일이 없는 동작(입력 칸으로·답 고르기·중단·터미널 시트·모드, ACTIONS 의 `noShell`)에는 스위치가 없다. 스위치는 바꾼 키와 함께 저장한다: 키 문자열 대신 `{ key, shell }`(저절로 정한 값과 같으면 그냥 문자열, 예전 형식도 그대로 읽는다). 「입력 칸에서도」 스위치는 없다(Ctrl·Alt·⌘ 조합은 입력 칸에서도, 맨 글자는 안 된다). 버튼의 키 표시와 단축키 창은 바꾼 키를 바로 따른다.
  - 빠른 이동(`public/switcher.js`): Ctrl+P(입력 칸에서도)나 Alt+P(셸 화면에서도; 셸 화면의 Ctrl+P 는 셸의 이전 줄이라 셸로 간다)가 화면 위쪽(두 칸이면 오른쪽 칸 위, 목록을 옆에 둔 채)에 찾기 창을 연다. 설정 카드처럼 테두리·모서리를 두고, 떠 있는 것들(가운데 확인 창, 메뉴 팝오버)과 같은 그림자(`--pop-shadow`)·나타남을 쓴다. 크기는 다른 앱의 팔레트(VS Code·Linear·Raycast)만큼: 두 칸이면 폭 760px(대화 열의 가장 좁은 폭), 높이 560px 안. 검색 칸은 단축키 찾기와 같은 부품(`.search-field`)이되 팔레트 안에서는 테두리 없이 카드의 맨 윗줄(17px)이고, 줄은 제목 한 줄(넘치면 …)에 마우스면 메뉴처럼 촘촘하다. 모든 호스트의 에이전트·셸을 이름·제목·작업공간·호스트로 거른다(소문자로 바꾼 부분 문자열, 띄어 쓴 낱말마다; 한글은 조합 중인 글자로도 바로 거른다). 줄은 목록의 줄 그대로다(`list.js` agentRow/termRow: 아이콘, 굵은 제목, 아래 작은 줄에 이름·시간과 작업공간·여러 호스트면 호스트, 목록과 같은 상태 이름, 안 읽음 점). 고른 줄은 목록의 연 줄처럼 초록 바탕과 왼쪽 막대. 빈 칸이면 설정 → 빠른 이동 → 「빠른 이동의 순서」를 따른다(`herdr-hub.paletteOrder`): 기본 「완료 먼저」는 답 필요 → 완료(끝났거나 아직 안 읽은 결과) → 작업 중 → 쉬는 중 → 셸, 「작업 중 먼저」는 완료와 작업 중을 바꾸고, 「최근 연 순」은 답 필요 다음을 상태와 상관없이 최근 순으로 둔다. 같은 무리 안에서는 이 기기에서 최근에 연 순서(`herdr-hub.recent`)이고, 무리가 바뀌는 곳에 작은 머리줄이 붙는다(↑↓ 는 건너뛴다). 지금 연 것은 맨 아래 「지금 보는 중」 아래에 흐리게 둔다(열자마자 리턴이 같은 것을 다시 열지 않게). 찾는 말을 치면 이름이 맞는 정도가 먼저이고, 같으면 이 차례를 따른다. ↑↓(Ctrl+J/K 도, 끝에서 처음으로 돈다)로 고르고 리턴(한글 조합이 끝난 뒤)이나 누르기로 연다 — 목록의 줄을 누른 것과 같고, 두 칸이면 오른쪽에 열며 Alt+↑/↓ 처럼 그 입력 칸에 포커스를 준다. Esc·Ctrl+[·뒤로(덮개의 Esc)·바깥 누르기·입력 칸 옆 「취소」(손가락으로 열었을 때만)·Ctrl+P 한 번 더로 닫는다. 아래의 키 안내 줄은 표에서 읽는다(↑↓ · Ctrl+J/K · 리턴 · Esc·Ctrl+[). 실제 키보드가 없을 듯하면(`keyboardLikely`) 그 줄을 숨기고, 손가락으로 열었으면 무엇을 치거나 ↑↓ 를 누르기 전에는 고른 줄 표시를 하지 않는다. 다른 시트가 열려 있으면 열지 않는다(브라우저 인쇄로 가지 않게 키만 먹는다).
  - 명령(`public/palette.js`, `switcher.js`, 시험은 `npm test` 의 `test/palette.test.js`): VS Code 의 명령 팔레트처럼 Ctrl+Shift+P(Mac ⌘⇧P)나 F1 이 빠른 이동을 곧바로 명령으로 연다(칸에 `>`; 입력 칸·셸 화면·시트 위에서도). 빠른 이동에서 맨 앞에 `>` 를 쳐도 명령이 되고, `>` 를 지우면 다시 에이전트·셸이다. 명령에서 Ctrl+P 는 빠른 이동으로, Ctrl+Shift+P·F1 한 번 더는 닫기. 목록은 지금 할 수 있는 일이다: 지금 연 것(에이전트·셸·워크스페이스)의 ⋯ 메뉴 항목 가운데 단축키 동작이 따로 없는 것(키 보내기·이름 바꾸기·나누기 …)이 「이 에이전트: …」 머리줄 아래 먼저, 그다음 단축키 표(`keymap.js` ACTIONS)의 동작이 표의 차례와 묶음(어디서나 · 대화·터미널 화면 · 목록)대로, 줄 끝에 그 자리에서 되는 키(`Keymap.hint`, Mac 은 ⌘)와 함께. 지금 할 수 없는 것은 숨긴다(`switcher.js` COMMAND_CAN: 일하는 중이 아니면 중단 없음, 두 칸이 아니면 사이드바 없음, 워크스페이스 화면에서는 끝내기 대신 워크스페이스 닫기 …). 이름은 그 자리에 맞게 바뀐다(「에이전트 끝내기」·「셸 끝내기」, 「줄바꿈 끄기」, 「사이드바 접기」), 대상이 있으면 이름 옆에 흐리게. 치는 말은 낱말마다 이름의 맨 앞 → 이름의 한 낱말의 앞 → 이름 안 → 동작 설명·키 이름 안 → 이름의 글자가 차례대로(「셸끝」 → 셸 끝내기) 순으로 맞춘다(`Palette.filter`). 리턴·누르기는 그 키나 메뉴 항목과 같은 함수를 부른다(`KEY_ACTIONS`, `paneAction`·`wsAction`; 중단은 확인 창, 되돌릴 수 없는 것은 늘 묻는다). 팔레트가 닫히고 그 기록 항목이 거둬진 뒤에 돈다.
  - 새로 만들기: Ctrl+N(Mac 의 앱은 ⌘N, Mac 이 아닌 브라우저 탭은 Alt+N)은 지금 연 에이전트·셸·워크스페이스의 작업공간에 새 에이전트를 바로 시작한다(그 작업공간의 새 탭, 양식 없이). 폴더는 Hub 가 정해 보낸다(`quick.js` startFolder, `app.js` startFolderFor): 연 에이전트·셸이 지금 있는 폴더, 워크스페이스 화면처럼 연 것이 없으면 그 워크스페이스의 **기본 폴더**(아래 「워크스페이스와 폴더」), 그것도 없으면 이 Hub 에서 그 워크스페이스의 에이전트·셸 중 마지막에 본 것(빠른 이동의 최근 목록)의 폴더, 그것도 없으면 보내지 않아 herdr 가 정한다(그 워크스페이스의 활성 탭 폴더). 워크스페이스 화면·⋯ 메뉴의 「새 셸 열기」도 같은 폴더에 연다. 종류·추가 옵션은 이 기기에서 마지막에 에이전트를 시작할 때 쓴 것(양식으로 시작하면 그 값을 기억한다, `localStorage` 의 `herdr-hub.lastAgent`, `quick.js`; 처음에는 Claude·옵션 없음; 그 호스트에 그 종류가 없으면 Claude), 이름은 서버가 붙인다. 시작하는 동안 「새 Claude 에이전트를 시작하는 중… · ~/Project/herdr-hub」(어디서 여는지, 홈은 `~`, 깊으면 마지막 두 단계; `rowtext.js` homePath) 알림이 뜨고, 그동안 다시 누르거나 키를 누르고 있어도 하나만 시작한다. 시작되면 그 대화가 열리고 메시지 칸에 커서가 간다(그새 다른 화면으로 갔으면 「열기」가 달린 알림만). 실패하면 알림. 아직 메시지가 없는 대화 화면에는 「종류·옵션 바꾸기」 링크가 있어 그 작업공간의 에이전트 시작 양식(`#/start/ws/<id>`, 따로 한 화면)을 연다 — 양식은 에이전트를 하나 더 시작하므로, 방금 연 빈 대화는 Alt+W 로 묻지 않고 닫으면 된다. 양식은 워크스페이스 화면·⋯ 메뉴의 「에이전트 시작」으로도 그대로 연다. 목록처럼 작업공간을 정할 것이 없으면 새 워크스페이스. Ctrl+Shift+N(Mac 의 앱은 ⌘⇧N, Mac 이 아닌 탭은 Alt+Shift+N)은 새 워크스페이스(`#/new`, 목록이 한 호스트로 걸러져 있으면 그 호스트, + 단추와 같다). 입력 칸에서도 되고, 셸 화면(Ctrl+N 은 셸의 다음 줄, Alt+N 은 readline 키; Mac 의 ⌘N 은 셸 화면에서도 된다)과 시트 위에서는 안 된다. Alt 짝은 Chrome 이 Ctrl+N·Ctrl+Shift+N 을 새 창으로 가져가는 곳(Mac 이 아닌 브라우저 탭)에만 둔다.

- 작업공간 탭(목록): herdr 의 호스트 → 워크스페이스 → 패널 순서. 워크스페이스마다 카드 하나(이름, 그 아래 한 줄에 여러 호스트를 함께 볼 때만 호스트 표시, ⋯ 은 워크스페이스 메뉴; 폴더는 없다 — 아래 「워크스페이스와 폴더」), 안에 패널 줄(에이전트 먼저: 아이콘·제목(두 줄까지), 오른쪽 끝에 시간(끝난 지 얼마, 작업 중이면 얼마나 — 작고 흐리게, 제목 첫 줄에 맞춤), 제목 아래 작은 줄에 「● 완료 · 이름 · 폴더」(상태는 색 점과 글; 이름은 제목이 그 이름으로 시작하면 적지 않는다, `rowtext.js` metaName). 답 필요만 시간 자리에 눈에 띄는 알약으로 남는다. 아이콘·시간·⋯ 은 제목 첫 줄에 맞춘다. 셸은 이름 아래 작은 줄에 폴더, 오른쪽에 「셸」. 마우스가 있는 화면(노트북)은 조금 더 촘촘하다: 제목 14px, 줄 50px(두 줄 제목 68px), 카드 머리 40px; 손가락은 16px·56px 그대로. 제목은 그 패널에 이름표가 있으면 이름표(`herdr pane rename`, 에이전트가 제 패널에 붙인 이름 — 셸 줄과 같다), 없으면 에이전트가 터미널에 쓰는 제목이다(`lib/hub.js` shapeAgent, `label` 도 함께 보낸다); 셸은 `>_`·프로그램 이름·「셸」). 줄의 폴더는 그 패널이 지금 있는 곳(`foreground_cwd`, 없으면 `cwd`)이고 — Claude 에이전트는 대화 기록이 말하는 작업 폴더(기록 줄마다 적히는 `cwd`, `cd` 를 따라간다; herdr 는 claude 를 띄운 폴더만 안다)가 아직 있으면 그것이다(`lib/hub.js` addGlance, `lib/transcript.js` lastCwd; 지운 worktree 처럼 없으면 패널 폴더, 다르면 상태에 `paneCwd` 로 패널 폴더도 싣는다; Ctrl+N·머리글·「/」 명령 목록도 이 폴더를 쓴다) — 폴더 이름이 워크스페이스 이름이나 그 줄의 이름과 같으면 적지 않고, 아니면 마지막 폴더 이름만 보인다(`robots_rcs`, 마우스를 올리면 전체 경로; `public/rowtext.js` `rowDir`, 시험은 `npm test`). 에이전트·셸 화면의 머리글 부제도 「워크스페이스 · 폴더」를 같은 방식으로 적는다(전체 경로는 툴팁). 셸 이름은 이름표 → 제목(경로면 프로그램 이름) → 폴더 이름 → 패널 id 순서로 늘 무언가 있다(`termName`). 상태 이름은 답 필요·작업 중·완료·쉬는 중(herdr idle; 예전 「대기」는 「내 답을 기다림」으로 읽혀 바꿨다). 카드 머리는 높이 전체가 워크스페이스 링크다. 워크스페이스가 없으면 가운데에 「워크스페이스가 없습니다」와 「새 워크스페이스」 버튼, 이 기기의 herdr 에 닿지 못하면 어느 기기인지와 확인할 것, 「연결 상태 보기」(설정 → 연결로 가서 그 칸을 위에 둔다)를 보인다. 첫 안내 줄(「옆으로 밀어 기기 바꾸기 · 길게 눌러 메뉴」, 호스트가 하나면 길게 누르기만)은 터치 기기에서 앱을 세 번 열 때까지, 또는 ✕ 를 누를 때까지 나온다(`herdr-hub.hint.hostswipe` 에 횟수, ✕ 면 `x`). 응답이 필요한 에이전트는 따로 모으지 않는다: 그 줄의 상태(답 필요)와 탭·활동 막대의 수로 알리고, 답은 그 에이전트를 열어 대화 화면에서 한다(휴대폰·두 칸 모두). 카드 순서는 응답 필요가 있는 것 → 작업 중이 있는 것 → 나머지, 그 안에서는 호스트 순서, 그다음 사람이 정한 카드 순서(없으면 herdr 순서). 상태가 바뀌면 바뀐 카드만 다시 그려서 스크롤 위치가 그대로다.

Read·Write·Edit 는 파일 이름 먼저(「http.js · herdr-hub/lib」). Skill 은 스킬 이름과 받은 인자(「design:design-critique」, 「loop · 5m /foo」). 대화에서 도구 줄을 펼치면 명령 전체가 결과 위에 나온다.
  - `lastReply`·`lastTool`: 각 호스트가 Claude 기록 끝 256KB 를 파일이 바뀔 때만 다시 읽어(`transcript.glance`, `public/inbox.js` `glance`) 상태에 붙인다. `lastReply` 는 완료·쉬는 중(끝난 때를 아는) 에이전트에만(완료 알림의 본문), `lastTool` 은 작업 중에만.
  - 메뉴(`actions.js` paneMenu·wsMenu): 에이전트·셸·워크스페이스마다 메뉴가 하나다. 그 화면의 ⋯ 이든 목록 줄을 길게 누른 것(또는 카드의 ⋯)이든 같은 항목이 같은 순서로 나온다: 할 일(에이전트: 중단·터미널 화면 보기·키 보내기·마지막 답 복사; 셸: 여기서 에이전트 시작·아래로/오른쪽으로 나누기·새 셸 열기, 그 셸 화면의 ⋯ 에서는 이어서 줄바꿈 끄기/켜기·한 줄 입력으로(키 직접 입력으로) 쓰기·색상 끄기/켜기(설정과 같은 값, `Prefs.set`); 워크스페이스: 에이전트 시작·새 셸 열기) → 관리(이름 바꾸기·워크스페이스 보기) → 빨간 끝내기·닫기(에이전트 끝내기·셸 끝내기·워크스페이스 닫기). 목록에서 열면 맨 위에 「대화 열기」·「셸 보기」·「워크스페이스 보기」가 하나 더 있다. 그 화면에서 연 메뉴는 단축키가 있는 항목 끝에 키를 보인다(키보드가 있을 때: 중단 Alt+. ×2, 터미널 화면 Alt+T, 끝내기 Alt+W, 워크스페이스 닫기 Alt+Shift+W). 손가락으로 연 메뉴 시트와 확인 창은 포커스를 창 자체에 두어 첫 항목이 골라진 것처럼 보이지 않고, 키로 연 것(과 두 칸의 팝오버)만 첫 항목(확인 창은 확인 단추, 되돌릴 수 없는 창은 「취소」)에 포커스를 준다(`core.js` lastInput). 키로 연 메뉴 시트에는 「취소」 단추가 없다(Esc·Ctrl+[).
  - 손가락용 크기: 손가락만 있는 기기(`pointer: coarse`)에서 설정의 고르기 단추·대화 위 작업 줄은 44px, 단축키 페이지의 ×·+·「셸」 탭의 스위치·「+2」도 44px, 설정 → 정보의 새로고침·지금 바꾸기, 답 필요 상자의 토글(터미널 화면·키 직접 보내기), 셸 출력의 「더 보기」, 연결 끊김 알림의 접기(›)도 44px(마우스 기기에서는 더 작다). 대화 속 도구 줄은 길게 늘어서면 답이 밀려나므로 36px. 마우스 기기(`hover: hover` 와 `pointer: fine`)에서는 펼치는 도구 줄도 28px 짜리 조용한 줄이다: 회색 바탕은 마우스를 올리거나 펼쳤을 때만, ▸ 는 이름 바로 앞에 있고 펼칠 것 없는 줄도 이름 자리를 맞춘다. 호스트 칩 글씨 12px.
  - 여백: 모든 padding·margin·gap 은 4·8 격자의 한 단계다(`style.css` 맨 위 `--sp-0`…`--sp-7`: 2·4·8·12·16·24·32·48px). 카드·설정 줄·메뉴 줄·토스트의 안쪽은 16px, 목록 줄의 아이콘과 글 사이 12px, 점과 글 사이 8px, 표 칸은 8px 12px(휴대폰은 옆 8px). 빠른 이동은 찾기 글자·묶음 이름·줄 아이콘이 왼쪽 24px 한 선이다.
  - 워크스페이스 화면(`#/ws/<id>`, `public/workspace.js`): 설정과 같은 묶음 카드다. 정보 카드(여러 호스트면 호스트; 아니면 카드가 없다. 「폴더」 줄은 없앴다: 워크스페이스에는 폴더가 없고, 폴더는 줄마다 있다), 「에이전트」와 「셸」은 목록과 같은 줄(아이콘·새 결과 점·시간·상태, 셸이 없으면 그 묶음은 없다), 「워크스페이스」 카드에 기본 폴더(Hub 가 기억하는 것, 마지막 두 단계와 ›, 누르면 `#/dir/ws/<id>`; 아래 「워크스페이스와 폴더」), 이름 바꾸기와 워크스페이스 닫기(빨간 글씨 줄, 누르면 확인 창). 할 일 둘(에이전트 시작, 새 셸 열기 = 새 탭에 셸)은 화면 맨 아래 고정 줄에 있어 엄지가 닿는다(알림 줄은 그 위에 뜬다). 머리글 이름은 두 줄까지 보이고, 부제는 여러 호스트일 때의 호스트와 에이전트·셸 수만(0 은 적지 않는다). 실시간 연결이 끊기면 머리글에 「끊김」 칩. 워크스페이스가 없으면(닫힘·없음, 호스트 오프라인, 연결 끊김) 그 까닭과 「작업공간으로」 단추를 보이고, 상태가 돌아오면 저절로 다시 그린다.
  - 뒤로 밀기(`backswipe.js`): 대화·셸·워크스페이스 화면에서 왼쪽에서 오른쪽으로 밀면 ‹(두 칸이면 ✕)를 누른 것과 같다. 설정도: 휴대폰은 작업공간으로, 두 칸이면 설정의 ✕(Ctrl+,)처럼 닫힌다. 페이지 전체(탭 막대 빼고)가 손가락을 따라오며 왼쪽에 옅은 그림자를 드리우고, 그 뒤에 돌아갈 화면이 iOS 처럼 보인다: 휴대폰은 남겨 둔 작업공간 목록 그대로(스크롤 위치째)가 폭의 30% 왼쪽에서 조금 어둡게 있다가 손가락과 함께 제자리로 오고, 두 칸이면 빈 오른쪽 칸. 뒤로가 다른 화면으로 가면(두 칸에서 에이전트 위에 연 설정) 예전처럼 페이지만 흐려지며 빠진다. 80px 넘게 밀거나 빠르게 튕기면 손을 뗀 속도 그대로 이어서 빠지고(`motion.js` 감쇠 용수철, 튀지 않음), 아니면 제자리로 돌아온다. 빠지고 나면 목록은 그 자리에 그대로 있다(빈 화면·다시 그리기 없음). 손가락 아래 것이 아직 왼쪽으로 스크롤될 수 있으면(옆으로 밀어 둔 넓은 표·셸 화면), 입력 칸, 시트 위, 머리글, 왼쪽 끝 20px(Android·iOS 의 가장자리 제스처)에서는 하지 않는다. 동작 줄이기 설정이면 손을 떼는 순간 바로.
  - 호스트 넘기기: 작업공간 목록에서 옆으로 밀면 호스트가 넘어간다(전체 → desktop → server …, Alt+←/→·호스트 칸과 같다; `tabswipe.js` → `list.js` stepHostFilter; 70px 넘게 밀거나 빠르게 튕기면). 호스트마다 목록이 나란히 있는 것처럼: 목록이 손가락을 따라가고 옆 호스트의 목록(밀기 시작할 때 그 자리에서 한 번 그린다, 2ms 안팎)이 함께 들어오며, 호스트 칸의 선택 표시가 민 만큼 옆 호스트 쪽으로 간다. 손을 떼면 그 속도 그대로 이어서 옆 목록이 제자리에 오고 호스트가 바뀐다(아니면 돌아온다; 동작 줄이기 설정이면 바로). 더 갈 호스트가 없는 쪽으로는 당길수록 덜 따라오다가(고무줄) 놓으면 돌아온다. 머리글(호스트 칸)은 그대로 있다. 휴대폰과 두 칸 화면의 사이드바에서 된다. 설정은 아래 탭(두 칸이면 활동 막대)으로 간다. 호스트가 하나면 넘기지 않는다. 두 탭의 화면은 한 번 그리면 남겨 두었다가 그대로 다시 붙이고 바뀐 것만 고친다(`list.js` `showTab`): 스크롤 위치도 그대로다. 휴대폰에서 에이전트를 열었다 돌아올 때도 같다. 설정의 알림 상태는 받아 둔 것을 바로 보이고 1분이 지났으면 뒤에서 다시 묻는다. 첫 움직임이 세로면 스크롤, 가로면 호스트 넘기기. 화면 왼쪽 끝 20px, 옆으로 스크롤되는 것(키 줄·넓은 표) 위, 입력 칸, 시트가 열린 동안, 대화·셸·설정 화면에서는 넘기지 않는다. 그래서 줄은 밀어서 열지 않는다. 줄의 「이름」·「닫기」는 길게(0.5초) 누르거나 ⋯ 로 여는 메뉴에 있다(텍스트 선택·콜아웃 없음). 닫기는 한 번 더 묻는다. 위 호스트 줄의 강조 박스는 실제 폭으로 움직이고(늘여 찌그러뜨리지 않는다), 칸 글자의 색도 박스를 따라 옮겨 가며 굵기는 절반을 넘을 때 넘어간다. 다 넘어간 순간 바뀌는 것이 없다. 호스트가 여럿이면 「작업공간」 아래 부제는 없다(바로 아래 호스트 칸과 같은 말이라서); 하나면 그 이름이다. 호스트 칸은 버튼이 칸에 다 들어가지 않으면(호스트 넷 이상, 긴 이름) 옆으로 스크롤되고 긴 이름은 「…」로 끝난다(글자 단위로 꺾지 않는다). 호스트 칸이 넘치면 고른 호스트가 칸 한가운데에 온다(양 끝의 것은 끝이 허락하는 데까지, `list.js` showChosenHost·segMid): 처음 그릴 때는 바로 거기, 누르거나 Alt+←/→ 뒤에는 미끄러져 가고(동작 줄이기면 바로), 옆으로 넘기는 동안에는 칸도 민 만큼 함께 스크롤되어 다 넘어간 때 이미 한가운데다. 그 밖에는 둔 자리 그대로다: 손가락·휠로 옮긴 칸은 다음 그리기에 되돌아가지 않고, 에이전트를 열었다 돌아와도(`tabPages` 가 옆 스크롤도 담는다) 그대로다. 스크롤되는 호스트 칸 위에서 시작한 옆 밀기는 그 칸을 스크롤한다.
  - 방금 본 대화로(`fwdchip.js`, 순수 판단은 `forward.js`, 시험은 `npm test`): 휴대폰에서 에이전트·셸을 나와(뒤로 밀기·‹·Esc) 작업공간 목록으로 오면 탭 막대 바로 위에 작은 칩 「방금 본 대화 · <이름> ›」(셸이면 「방금 본 셸」, 이름이 길면 줄임)이 뜬다. 누르면 그 줄을 누른 것처럼 다시 열린다(새 기록 항목이라 거기서 뒤로는 다시 목록). 30초가 지나거나, 목록을 200px 넘게 스크롤하거나, 다른 것(에이전트·셸·워크스페이스·폼)을 열거나, ✕·아래로 쓸기로 사라진다. 떠 있는 동안 목록 아래에 그만큼 여백을 두어 마지막 줄을 가리지 않는다. 두 칸에는 목록이 늘 옆에 있어 칩이 없다. 키보드로는 목록에서 Alt+`(위). 「다시 갈 곳」은 칩이 사라져도 다른 것을 열 때까지 남는다(그 에이전트·셸이 닫히면 없다).
  - 오른쪽 끝에서 밀기: 작업공간 목록에서 화면 오른쪽 끝 24px 안에서 시작해 왼쪽으로 밀면 그 「다시 갈 곳」으로 들어간다 — 뒤로 밀기를 뒤집은 것: 대화가 오른쪽에서 손가락을 따라 목록 위로 들어오고, 목록은 조금 왼쪽으로 밀리며 어두워진다(밀기 시작하는 순간 대화를 열어 화면 밖 오른쪽에 두고, 뒤로 밀기의 그림 `backFrame`·`peekBuild` 를 그대로 쓴다). 80px 넘게 밀거나 빠르게 튕기면 그 속도로 제자리에 들어가고, 아니면 다시 오른쪽으로 빠지며 목록으로 돌아온다. 갈 곳이 없으면 끝에서 밀어도 여느 때처럼 호스트 넘기기다. 다른 데서 시작한 가로 밀기도 호스트 넘기기 그대로다. 설정 → 입력 「오른쪽 끝에서 밀어 방금 본 대화로」(`herdr-hub.edgeForward`, 기기마다): iOS(iPhone·iPad)는 처음에 켜져 있고, Android·그 밖은 꺼져 있다(Android 제스처 탐색은 양쪽 끝을 시스템 뒤로 가기에 쓴다). 동작 줄이기 설정이면 손을 뗄 때 바로 연다.
- 워크스페이스와 폴더: herdr 의 워크스페이스에는 폴더가 없다(`workspace get` 에 cwd 가 없다). `workspace create --cwd` 는 첫 탭이 열릴 곳일 뿐이고, 새 탭은 `tab.create` 에 `cwd` 를 주면 거기서, 안 주면 **그때 그 워크스페이스의 활성 탭** 폴더에서 열린다. 그래서 Hub 는 워크스페이스에 폴더를 적지 않고(목록 카드·워크스페이스 화면), 패널마다 제 폴더를 보이며, 새 탭을 열 때 폴더를 정해 보낸다(Ctrl+N, 에이전트 시작 양식). API: `POST /api/workspaces/<id>/tabs|agents` 의 본문에 `cwd`(선택; 새 워크스페이스의 폴더와 같은 검사 `lib/validate.js` cleanCwd — 그 호스트의 절대 경로, 있는 폴더)를 넣으면 herdr `tab.create` 에 그대로 넘긴다. 없거나 빈 값이면 예전처럼 herdr 가 정한다(필드를 더하기만 했으므로 `API_VERSION` 은 그대로; 시험은 `test/tabcwd.test.js`, 가짜 herdr 소켓 `test/fixtures/fakeherdr.js`).
  - 기본 폴더: herdr 에는 없어서(API 에 워크스페이스 폴더가 없고, 설정 `new_cwd` 는 모든 워크스페이스에 한 값, `report-metadata` 는 길어야 24시간 뒤 사라지는 표시용) 그 워크스페이스가 있는 호스트의 Hub 가 기억한다: `data/wsdirs.json`(`{ <workspace_id>: { cwd, label } }`, `lib/wsdirs.js`). 상태의 워크스페이스에 `defaultCwd` 로 실리고(피어 것은 그 피어가 싣는다), `POST /api/workspaces/<id>/dir {cwd}` 가 정한다(같은 cleanCwd 검사, 비우면 지운다). 새 워크스페이스를 만들면 그 폴더가 기본 폴더가 된다. 정하는 곳: 워크스페이스 화면의 「기본 폴더」 줄과 ⋯ 메뉴의 「기본 폴더 정하기」(명령에도 나온다)가 여는 `#/dir/ws/<id>`(최근 폴더·폴더 찾아보기·경로 직접 입력, 「저장」·「기본 폴더 지우기」), 에이전트 시작 양식의 「이 워크스페이스의 기본 폴더로 정하기」. Ctrl+N 에서는 연 에이전트·셸의 폴더가 먼저다(위). herdr 는 워크스페이스 id 를 다시 띄워도 지키지만, 닫힌 id 를 재시작 뒤 새 워크스페이스에 다시 준다(w3 을 닫고 herdr 를 다시 띄우면 다음 것이 또 w3). 그래서 기본 폴더는 그 워크스페이스가 있는 동안만 둔다: herdr 목록에서 사라지면 지우고, 이 프로세스가 처음 보는 id 의 이름이 적어 둔 이름과 다르면(Hub 가 꺼진 사이에 다른 워크스페이스가 그 id 를 받았을 수 있다) 지운다. Hub 가 본 이름 바꾸기(지난 목록에 있던 id)는 이름만 따라 바꾼다. 필드와 경로를 더하기만 했으므로 `API_VERSION` 은 그대로다(예전 피어의 워크스페이스는 기본 폴더가 없을 뿐; 시험은 `test/wsdirs.test.js`, `test/tabcwd.test.js`). 기본 폴더가 지워진 폴더면 Ctrl+N 이 「폴더를 찾을 수 없습니다」 같은 알림으로 실패하니 기본 폴더를 다시 정한다.
- 관리: 새 워크스페이스(호스트·폴더(「첫 탭이 열릴 폴더 · 이 워크스페이스의 기본 폴더가 됩니다」)·이름, 바로 에이전트 시작; 칸마다 이름표가 그 칸에 묶이고 「워크스페이스 이름」·「에이전트 이름」을 나눠 부른다. 최근 폴더가 하나뿐이면 미리 골라 둔다. 폴더 없이 「만들기」를 누르면 폴더 칸이 빨갛게 「폴더를 고르세요」를 말하며 화면에 들어오고 첫 최근 폴더(없으면 「폴더 찾아보기」)에 포커스가 간다), 에이전트 시작(기존 셸 패널 또는 새 탭; 새 탭이면 폴더 칸이 있어 Ctrl+N 이 쓸 폴더로 미리 채워 두고, 최근 폴더는 그 워크스페이스의 패널들이 있는 폴더 먼저, 비우면 herdr 가 정한다 — 고른 폴더는 그 한 번만 쓰고, 「이 워크스페이스의 기본 폴더로 정하기」를 켜면 기본 폴더로도 정한다; 종류·추가 옵션(인자)·이름, 이름이 틀린 동안 「시작」은 꺼져 있다. 키보드로 열면 「에이전트」 칸에 포커스가 가고, 어느 칸에서나 Ctrl+리턴(⌘+리턴)이 「시작」·「만들기」다(`keymap.js` LOCAL 「폼」). 뒤로는 열기 전 화면(보던 에이전트·셸)으로 가고, 두 칸에서는 다른 오른쪽 화면처럼 머리글 끝의 ✕ 다), 일반 터미널 패널(화면 보기, 명령 한 줄, Ctrl+C·Enter·↑↓·Tab·Esc), 새 탭·패널 나누기, 이름 바꾸기·닫기. 닫기는 늘 페이지 안에서 한 번 더 묻는다.
  - 폴더 고르기: 최근 폴더를 큰 줄로 보여 주고 한 번 누르면 고른다. 「폴더 찾아보기」는 아래에서 올라오는 시트로, 경로 조각(누르면 그 폴더로), 바로 가기(홈·`~/Project`·`~/src`·Desktop·Documents, Windows 는 `C:`·`D:` 중 있는 것), 하위 폴더 목록, 「↑ 상위」, 늘 보이는 「이 폴더 선택」, 「새 폴더」(이름을 받아 만들고 바로 고름)가 있다. Windows 는 드라이브 루트의 상위가 드라이브 목록이다. 경로를 직접 적는 칸은 「경로 직접 입력」 뒤에 있다. 호스트를 바꾸면 고른 폴더와 찾아보기 위치가 처음으로 돌아간다. 이름을 비우면 폴더 이름이 된다.
  - 최근 폴더에서 빼기: 최근 폴더는 기록이 아니라 그 호스트의 지금 에이전트·셸의 폴더(`lib/hub.js` recentCwds, 많은 것 먼저 12개)라서, 줄 오른쪽의 ✕(제 단추, 「<이름> 최근 폴더에서 빼기」)는 그 폴더를 최근 폴더에서 숨긴다. 확인 창 없이 빼고 알림의 「되돌리기」로 되돌린다. 숨긴 목록은 그 폴더가 있는 호스트의 데이터다: `data/hidden-cwds.json`(경로 배열, 최대 200, 오래된 것부터 빠짐, `lib/hiddencwds.js`, tmp 에 쓰고 rename), `POST /api/recent/hide|show {cwd}`(피어 것은 `/api/peers/<id>/recent/…` 로 넘긴다; 없는 폴더도 숨길 수 있다). 그 호스트가 recentCwds 에서 빼고 `/api/host` 의 `hiddenCwds` 로 알려 양식이 워크스페이스 자기 패널의 폴더에서도 뺀다 — 그래서 모든 기기가 같다. 같은 폴더인지는 끝의 구분자를 떼고 Windows 에서는 대소문자·`/`·`\` 를 가리지 않고 본다(recentCwds 도 같은 기준으로 센다). 숨긴 폴더도 직접 입력·찾아보기로 쓸 수 있고, 거기에 탭·워크스페이스를 만들면 다시 나온다. 「선택됨」 칸과 기본 폴더는 건드리지 않는다. 필드와 경로를 더하기만 했으므로 `API_VERSION` 은 그대로다(예전 피어에서는 ✕ 가 「빼지 못했습니다」로 끝난다; 시험 `test/hiddencwds.test.js`).
  - API: `GET /api/dirs?path=<절대 경로>` → `{path, parent, sep, crumbs, dirs}`(하위 폴더 이름만, 대소문자 무시 정렬, 500개까지; 비우면 홈; 읽을 수 없으면 `denied: true`). `?drives=1` 또는 `path=::drives` 는 드라이브 목록. 점·`$` 로 시작하는 것, `node_modules`·`AppData`·`System Volume Information` 같은 것, 열 수 없는 링크(Windows 옛 프로필 정션)는 숨긴다. 링크 확인은 1초 안에 끝나지 않으면 건너뛰고 다시 보지 않는다(macOS `/home` 자동 마운트가 멈춤). `POST /api/dirs {parent, name}` 은 새 폴더를 만들고 `{path}` 를 돌려준다 — 이름은 100자까지, `/ \ : * ? " < > |`·제어 문자·`.`·`..`·끝의 점/공백·`CON` 같은 예약 이름은 `400 bad_dir_name`, 이미 있으면 `409 dir_exists`. `/api/host` 는 `places`(있는 바로 가기 폴더)도 준다.

- 에이전트 보기: 패널 종류마다 보기가 하나다. Claude 에이전트는 늘 대화(기록)를 보여 준다(대화/화면 탭은 없앴다). 기록이 없는 다른 에이전트(codex 등)는 그 자리에 터미널 화면을 보여 준다(`agent !== 'claude'`, 서버의 `supported: false` 와 같은 기준). 막 시작해 기록이 아직 없는 Claude 는 「아직 대화 기록이 없습니다」. 일반 셸 패널은 전처럼 `#/term/<pane>` 터미널 보기다. 셸이 닫혔으면 키 줄과 명령 줄을 없애고 본문에 「이 셸은 닫혔습니다」와 「작업공간으로」(두 칸에서도: ✕ 와 같은 일이지만 본문 안에서 바로 보이게), 머리글에는 마지막으로 알던 셸 이름과 「닫힘 · 워크스페이스 · 폴더」를 남기며 ⋯ 는 숨긴다, 호스트가 오프라인이면 「호스트가 돌아오면 이 셸이 다시 보입니다」(단추 없이)를 보여 준다. 이미 읽은 화면이 있으면 지우지 않고 그 위 띠로 「이 셸은 닫혔습니다 · 아래는 닫히기 전의 마지막 화면입니다」를 한 번 말한다. 셸(호스트)이 돌아오면 저절로 되돌아간다(`shell.js` termGone). 머리글 제목은 에이전트처럼 18px·두 줄까지다.
  - 머리글: 제목은 목록 줄과 ⋯ 메뉴와 같은 대화 제목(`rows.js` rowLabel), 에이전트 이름은 그와 다를 때 부제에(「작업 중 · 18분 · shop-api · desktop」; 워크스페이스·폴더는 이름에 더할 것이 있을 때만). 넓은 화면은 제목 옆에 사용량 칩과 상태·시간 배지. 휴대폰 폭(760px 미만)은 제목 줄을 제목에 내준다: 18px 두 줄까지, 상태·시간은 부제 맨 앞, 사용량 칩은 「21%」만. 권한 모드 칩은 머리글이 아니라 메시지 칸 바로 위 한 줄(`#d-ctools`, 「권한: 편집 허용」)에 있다 — 칩 둘이 머리글을 밀어 부제가 잘리던 것을 풀었고, 모드는 메시지를 보낼 때 뜻이 있다. 키보드가 올라오면 그 줄은 숨는다. 에이전트 종류는 claude 가 아닐 때만 부제에 쓴다. 키보드가 올라오면(`:root.kb`, Android 처럼 창이 줄면 높이 520px 이하) 휴대폰 머리글은 한 줄이 된다: 이름 한 줄, 부제는 숨기고 상태는 이름 앞 색 점, 위아래 여백도 줄인다(`.detail > .bar` 공통이라 셸 화면도 같다). 답 필요 동안 모드 칩은 숨긴다(⇧Tab 이 질문에 간다). 모드 칩을 누르면 바로 바뀌지 않고 「권한 모드」 메뉴가 열린다(넓은 화면은 칩 옆 팝오버, 휴대폰은 아래 시트): 수동 승인·편집 허용·계획·자동, 그 아래 따로 빨간 「권한 우회」, 지금 것에 ✓(키로 열면 그 줄에 포커스). 고르면 Shift+Tab 을 한 번씩 보내고 매번 바닥 줄을 다시 읽어(`mode.js` reachMode) 그 모드가 될 때까지 간다 — Claude Code 의 순서는 버전과 세션(권한 우회는 그렇게 시작했을 때만)에 따라 달라 가정하지 않는다. 한 바퀴를 돌아도 안 나오면 「「권한 우회」 모드는 이 세션에서 고를 수 없습니다」라 하고 그 에이전트의 메뉴에서는 그 줄이 꺼진다. 키가 아무것도 바꾸지 않으면 바로 멈추고 「모드를 바꾸지 못했습니다」. 칩이 제목 옆이라 잘못 누르기 쉬워 한 번에 바뀌던 것을 메뉴로 바꿨다(메시지 칸의 Shift+Tab 은 일부러 치는 키라 그대로 한 단계).
  - 에이전트가 없을 때: 끝났거나 닫혔으면 본문에 「이 에이전트는 끝났습니다」와 「여기서 새 에이전트 시작」(이 화면에서 본 적이 있고 그 워크스페이스가 남아 있으면)·「작업공간으로」. 호스트가 오프라인이면 읽어 둔 대화는 그대로 두고, 없으면 「<호스트> 에 닿지 않습니다 — 돌아오면 다시 보입니다」. 둘 다 입력 칸·첨부와 ⋯ 를 숨긴다.
  - 셸 모드(`!명령`): 기록의 `<bash-input>` 은 내 말풍선 「! 명령」(고정폭), `<bash-stdout>`·`<bash-stderr>` 는 그 아래 고정폭 상자로 보여 준다. 12줄이 넘으면 접고 「N줄 더 보기」. 색 코드는 버리고 8000자에서 자른다. stderr 는 stdout 이 함께 있을 때만 붉게(실패한 명령은 Claude Code 가 출력을 모두 stderr 로 남긴다).
  - 슬래시 명령(`/clear`, `/model opus`, 스킬): 기록에는 `<command-name>` 항목으로 남지만 대화에 보이지 않는다. 서버는 그것을 메시지에서 빼서 응답의 `commands`(`{ text, id, after }`, `after` 는 그 앞 메시지의 id, 맨 위면 null, 최근 20개)로 따로 싣고(`lib/transcript.js` commandsOf; 메시지 수·목록·앞 대화 페이지에는 들어가지 않는다), 앱은 Hub 에서 보낸 명령의 「보내는 중」 말풍선을 보낸 자리 뒤에 같은 명령이 오면 바로 지운다(`chatkeep.js` cmdSeen; `/clear` 는 새 대화의 맨 위에 온다). `commands` 가 없는 옛 호스트에서는 전처럼 쉬는 중 60초 뒤에 사라진다.
  - 작업 줄: 작업 중일 때만 머리글 아래에 한 줄. 3초마다 `screen?source=visible`(맨 글)을 읽어 `public/activity.js` 가 Claude 의 스피너 줄(`✻ Flowing… (1m 17s · ↓ 5.1k tokens)`)에서 활동 낱말·경과 시간·토큰을, 그 위 도구 줄(`⏺`/Windows `●`)에서 마지막 도구를 읽는다(시험은 `npm test`). 화면에 도구가 없으면 이번 차례 기록의 마지막 도구를 쓴다. 줄은 「작업 중 · 경과 시간 · 도구」 차례이고, 도구가 없으면 그 자리에 활동 낱말을 쓴다. 스크린리더는 줄 내용과 「누르면 터미널 화면」을 함께 읽는다. 못 읽으면 「작업 중」과 작업 중이 된 뒤(이 화면에서 본 때부터) 지난 시간. 시간은 읽는 사이에도 1초마다 간다.

- 정적 파일(`lib/http.js`, 시험은 `npm test`): 저장소의 `index.html` 에는 `?v=` 가 없다. 서버가 `index.html` 을 내줄 때 그 안의 로컬 `src`/`href`(스크립트·CSS·아이콘. 매니페스트만 빼고 — 설치된 앱이 그 주소를 쥐고 있을 수 있다)마다 `?v=<그 파일 내용 해시 앞 8자>` 를 붙이고, 빌드 정보 `<meta name="herdr-hub-build">` 를 넣는다(`indexPage`). 그래서 손으로 올릴 번호가 없고, 배포 뒤에는 바뀐 파일만 새 주소라 다시 받는다. `?v=` 가 지금 해시와 같은 요청은 `max-age=31536000, immutable`(다시 묻지 않는다). 다른 `?v=`(배포 전의 페이지가 부르는 옛 주소)도 404 가 아니라 지금 파일을 주되 `no-cache` 로 줘서 옛 주소에 새 내용이 굳지 않는다. `index.html`·`sw.js`·매니페스트는 `no-cache` 에 내용 해시 ETag 라 늘 다시 묻고, 그대로면 `304` — `index.html` 의 ETag 는 고친 페이지의 해시라 어느 파일이 바뀌어도 바뀐다. 파일 해시는 크기·수정 시각이 바뀔 때 다시 센다. 글 파일은 처음 쓸 때 한 번 brotli·gzip 으로 줄여 메모리에 두고 `Accept-Encoding` 에 맞춰 보낸다. HEAD 도 된다. API 응답(JSON)도 1 KB 넘으면 그때그때 gzip 으로 보낸다(150개 대화 212 KB → 63 KB, 약 2 ms). 허브는 피어에게도 gzip 을 달라고 해서 받은 그대로 넘기고(브라우저가 gzip 을 받지 않으면 풀어서), 예전 피어의 평문도 받는다. 실시간 연결(`/api/stream`)은 압축하지 않는 대신, `?delta=1` 로 연 연결(지금의 페이지와 허브)에는 처음 한 번만 상태 전체(`event: state`)를 보내고 그 뒤로는 바뀐 것만 보낸다(`event: patch`, `public/statepatch.js`, 시험 `test/statepatch.test.js`): 바뀐 맨 위 필드는 통째로, 항목 목록(`hosts` `agents` `terminals` `workspaces`)은 항목마다 — 그대로인 항목은 열쇠(`desktop|w1-p2`)만 — 보내 순서와 빠진 것도 그 안에 있다. 에이전트 150 개 중 하나가 바뀌면 53 KB 대신 몇 KB. 사건마다 `id:` 가 그 상태의 번호이고 패치는 `base`(어느 상태에서 왔는지)를 싣는다. 받는 쪽이 가진 상태와 `base` 가 다르거나 모르는 열쇠가 오면 연결을 다시 열어 전체를 받는다. `?delta=1` 없이 연 연결(예전 페이지·예전 허브)은 예전처럼 매번 전체를 받고, 예전 피어는 그 질의를 모른 채 전체를 보내므로 API 버전은 그대로다. 두 번째로 열 때는 `index.html` 의 304 와 실시간 연결뿐이다.
- 빌드 이름(`lib/build.js`): `1.0.523` = `package.json` 의 major.minor(큰 개편 때만 손으로 올린다) + 커밋 수(`git rev-list --count HEAD`). `deploy.sh` 가 배포본에 `build.json`(`{ version, commit, sha, time(커밋 시각), dirty }`, git 에는 안 넣는다)을 써서 보낸다 — 호스트에는 `.git` 이 없다. 커밋 안 한 것이 있으면 `dirty`(「+dirty」). `build.json` 이 없으면(저장소에서 바로 돌릴 때) git 에서 같은 것을 읽고, git 도 없으면 `dev`. 서버는 시작할 때 한 번 읽고 로그 첫머리에 적는다.

- 새 버전(`public/update.js`, `app.js`): 설치된 앱은 며칠씩 메모리에서 이어 열려 배포 뒤에도 옛 코드로 돈다. 서버는 자기 빌드(`{ version, commit, sha, time, dirty, api, id }`; `id` 는 빌드와 모든 파일 해시로 만들어 같은 커밋의 dirty 배포도 다르다)를 실시간 연결의 첫 메시지(`event: version`)와 `GET /api/version` 으로 알려 주고, 같은 것을 `index.html` 의 meta 에 넣어 준다. 앱은 연결이 (다시) 붙을 때와 앞으로 돌아올 때(`visibilitychange`, `pageshow`) 자기가 받은 빌드와 `id` 가 같은지 본다(더 새것인지가 아니라 다른지 — 되돌린 배포도 새 빌드다). 다르면: 앱이 막 앞으로 돌아왔거나 화면에 없거나 「멈춰 있고」(화면에는 보이지만 다른 창이 초점을 갖고, 이 페이지에 키·터치·클릭·휠이 60초 없음 — 모니터에 띄워 두고 다른 창에서 일할 때; 초점이 Hub 에 있는 채 가만히 읽는 중은 아니다, `Update.away`), 시트·메뉴·빠른 이동이 닫혀 있고, 입력 칸에 치는 중이 아니고, 메시지 칸에 안 보낸 글·사진이 없고, 보내는 중·답 적는 중이 아니면 스스로 다시 연다(주소 `#` 그대로, 글은 저장해 두고). 다시 열기 전에 `fetch('/', {cache:'reload'})` 로 새 `index.html` 을 받아 HTTP 캐시도 새로 하고, 그 meta 가 정말 다른 빌드일 때만 연다. 같은 빌드는 10분 안에 두 번 시도하지 않는다(sessionStorage). 그 밖에는 배포가 하루에도 수십 번이고 옛 화면은 제 파일끼리 그대로 돌므로 묻지 않는다: 설정 아이콘(두 칸은 레일의 ⚙, 한 칸은 탭 막대의 「설정」)에 점만 달리고(툴팁 「설정 — 새 버전 있음」), 설정 → 정보가 언제 바뀌는지 말한다. 30초마다 다시 보아 안전해지면(멈춰 있음, 보내기가 끝남, 시트가 닫힘) 그때 연다. 서버의 API 버전(`lib/hub.js` `API_VERSION`)이 이 화면의 것과 다를 때만(`Update.mustReload`) 돌아오기를 기다리지 않고 나머지 조건만 맞으면 곧바로 열고, 그동안 맨 위에 「● 이 화면이 서버와 맞지 않습니다. 새로고침하면 고쳐집니다 · 새로고침」 띠가 뜬다(✕ 없음, 점은 「작업 중」의 주황, 앱 화면은 그 아래로 내려가 머리글을 가리지 않는다). 1.0 이전 앱(숫자 `?v=` 를 견주는 코드)도 새 빌드를 알아보도록 응답에 `v`(커밋 수, 115 보다 크다)를 함께 싣고, `index.html` 머리에 `<!-- … <script src="/app.js?v=<커밋 수>"> -->` 주석을 둔다 — 옛 `versionOf` 가 그 숫자를 읽는다. 모든 기기가 1.0 이후로 넘어가면 지워도 된다.

  - 보내는 중 칩: herdr 는 셸 커서 위치를 주지 않아(0.9.3 의 API 에 터미널 커서가 없다; `cursor` 는 복사 모드의 것뿐) 커서는 그리지 못한다. 대신 키 직접 입력에서 친 키가 아직 셸에 닿지 않았으면(150ms 넘게) 키 줄 위 오른쪽에 「보내는 중: ls -la⏎」 칩이 뜨고(`keys.js` describeRaw), 응답이 오면 사라진다. 보내기에 실패하면 그 칩이 경고색으로 「보내지 못한 키: … · 까닭」을 남긴다(다음 키나 칩을 누르면 사라짐). 다른 셸에서 친 키가 실패하면 알림 줄로 알린다.

Android 의 뒤로·덮개의 Esc 는 맨 위 층만 닫고(겹쳐 있으면 한 번에 하나) 페이지를 떠나지 않는다 — 페이지가 사용자 활성화를 받았는지와 상관없다(Chrome 은 활성화 없이 넣은 기록 항목을 뒤로에서 건너뛰어, `?v=100` 의 기록 항목 방식은 덮개의 Esc 에 앱이 내려갔다). 다만 그 사이에 누르기·키 입력 없이 겹겹이 연 층은 Chrome 이 한 묶음으로 보아 뒤로 한 번에 함께 닫힌다. 다른 길(Esc·Ctrl+[·✕·바깥·고르기)로 닫으면 그 watcher 를 없앤다. 앱의 Esc·Ctrl+[ 는 keydown 에서 `preventDefault` 하므로 Chrome 이 따로 닫기 요청을 내지 않아 한 번에 한 층만 닫힌다. CloseWatcher 가 없는 곳(iOS Safari)에서만 예전처럼 기록 항목을 쓴다(`public/backstack.js`): 층마다 같은 주소의 항목을 하나 넣고(`history.state.layer` = 몇 겹째인지), 뒤로·iOS 가장자리 쓸기가 그 항목을 꺼내며 층을 닫는다. 다른 길로 닫으면 그 항목을 `history.back()` 으로 거두고, 메뉴에서 고른 것이 여는 다음 페이지·시트는 그 거둠이 끝난 뒤에 연다. 빠른 이동에서 다른 페이지를 고르면 그 항목 자리를 새 페이지가 갖는다(`replaceState`). 알림 열기처럼 층이 열린 채 주소가 바뀌어 남은 항목은 뒤로가 저절로 건너뛴다. 두 방식을 함께 쓰지 않는다(뒤로를 두 번 눌러야 하게 된다). 한계: 층이 열려 있을 때만 돕는다. 앱의 첫 화면에서 아무것도 열려 있지 않을 때의 뒤로(덮개의 Esc)는 여전히 앱을 내린다 — 앱 안의 Esc 는 Ctrl+[ 나 키 줄의 Esc.

- 키가 화면에 보이기까지(`lib/echo.js`, `keys.js` `queueRaw`·`termReadDue`, 시험은 `npm test`): 요청은 한 번에 하나이고, 가는 동안 친 키는 다음 항목에 모인다. 서버는 항목의 글을 먼저, 키를 다음에 치므로 키는 글만 있는 항목에도 붙는다(`ls⏎` 가 한 번에 간다; 키 다음에 친 글은 새 항목). 글과 키가 함께면 herdr 호출 하나(`pane.send_input`; herdr 가 이름이 없는 PgUp 같은 키가 있으면 예전처럼 둘). 키 응답의 화면은 고정 40ms 를 기다리지 않고 메아리가 화면에 오는 대로 읽는다: 친 글이면 마지막 줄의 끝 + 친 글이 그 패널의 지난번 화면에 없을 때 herdr 의 `pane.wait_for_output` 으로 기다린 뒤 읽고(보통 3–8ms; `timeout_ms` 는 정수여야 한다 — 소수면 herdr 가 거절해 기다리지 않고 바로 읽었다. herdr 0.9.3 은 40ms 제한에도 ~105–210ms 뒤에 답하므로 기다림은 Hub 쪽에서 40ms 에 끝낸다), 아니면(키, 또는 힌트·줄 중간 편집처럼 그 무늬가 안 맞을 때) 5·15·40ms 에 읽어 지난 화면과 달라지면 그만 읽는다 — server 의 herdr 는 호출마다 가끔 ~100ms 멈추므로 많이 읽지 않는다. 화면에 아무것도 바뀌지 않는 키는 예전처럼 40ms 뒤에 읽는다. `/keys` 는 상태를 새로 읽거나(`refresh`) 실시간 연결로 알리지 않는다(Enter 가 있으면 500ms 뒤 한 번; 에이전트 시작은 herdr 이벤트가 알린다). 화면은 키를 친 뒤 3초 동안뿐 아니라 지난 3초 안에 화면이 바뀌었으면(출력이 계속 나오면) 300ms 마다 읽고, 앱이 앞으로 돌아오면 바로 읽는다.
- 셸의 실시간 연결(`lib/ws.js`·`lib/live.js`·`public/live.js`·`public/screendiff.js`, 시험은 `npm test`; API 2): 셸 화면이 열려 있는 동안 WebSocket 하나(`GET /api/panes/<id>/live?lines=&format=`, 피어의 셸은 `/api/peers/<host>/panes/<id>/live` 를 허브가 피어의 같은 주소로 잇는다)로 키 직접 입력의 키가 치는 대로 올라가고(키마다 번호, 호스트가 그 순서대로 친다; 하나가 끝나기를 기다리지 않는다), 화면은 그 패널의 호스트가 바뀔 때만 내려보낸다. 호스트는 연결마다 일꾼 하나가 herdr 를 부른다: 밀린 키를 페이지의 줄처럼 묶어 한 번에 치고(`ls⏎` 를 빨리 치면 호출 하나), 더 밀린 것이 없으면 위의 메아리 기다리기(40ms 까지)로 읽어 보낸다. 더 밀린 키가 있으면(빨리 치는 동안) 그 키를 치면서 옆에서 화면을 한 번 읽어 보내므로, herdr 가 뒤의 키를 붙잡고 있어도 앞의 키는 화면에 나온다. 화면은 마지막으로 보낸 것보다 나중에 시작한 읽기의 것만 보낸다(늦게 온 읽기가 옛 화면을 되돌리지 않는다). 그 밖에는 40ms 마다, 키도 화면 변화도 5초 넘게 없으면 150ms 마다 읽는다(`HERDR_HUB_LIVE_IDLE_MS`; 연결 도우미를 끈 Mac 은 40 — 그 herdr 는 드물게 부르면 멈춘다). 읽기는 키를 막지 않는다: 읽기가 나가 있는 동안 온 키는 곧바로 치고, 키보다 먼저 시작한 읽기의 화면은 보내지 않는다. herdr 호출이 Node 길로 갈 때(아래 「herdr 연결 도우미」가 꺼졌거나 아직 안 떴을 때)만 붙잡힘을 피하는 우회가 돈다: Mac 의 herdr 는 그 길의 호출 3분의 1쯤을 ~105ms 붙잡지만 그 사이 보낸 두 번째 호출은 대개 바로 답하므로, 화면 읽기와 메아리 기다리기는 15ms·30ms 안에 답이 없으면 한 번 더 보내 먼저 온 답을 쓴다(`hedge`; 키는 다시 보내지 않는다). 키는 다시 보낼 수 없는 대신, herdr 를 깨워 두는 호스트에서는 키를 치기 3ms 전에 `ping` 을 하나 보낸다(30번에 13–15 → 2–3). 키 직접 입력의 HTTP 길에도 같다. 도우미가 호출을 나르는 동안은 붙잡히지 않으므로 셋 다 쉰다(같은 herdr 에서 우회를 켜 두면 메아리 p50 6 → 10ms, 얻는 것은 없다). 보내는 것은 처음 한 번만 화면 전체이고 그 뒤로는 바뀐 줄만이다(위에서 밀려 나간 줄 수·그대로 둘 줄 수·새 줄·끝에서 그대로 둘 줄 수; - 셸 예측 입력(`public/predict.js`, 시험은 `npm test` 의 `test/predict.test.js`; 설정 → 입력 → 「셸 예측 입력」 자동·켜기·끄기, 기기마다): 키 직접 입력에서 프롬프트에 친 글자를 호스트의 메아리보다 먼저 caret 자리에 그리고(mosh 방식), 호스트의 다음 화면이 맞다고 하면 그대로, 다르게 그리면 예측을 모두 바로 지운다. herdr 는 커서 위치를 주지 않으므로 메아리로 찾는다: 한 묶음(epoch)의 첫 키는 그리지 않고 적어만 두었다가, 화면의 마지막 빈 줄 아닌 줄에서 그 글자가 앞부분이 비지 않은 프롬프트 뒤에 나타나고 그 위 줄들이 그대로면 그 자리가 caret 이다. 그다음 키부터 바로 그리고, 메아리가 올 때마다 확인한다(그 키가 셸에 닿은 뒤 두 번째 화면까지 안 보이면 틀린 것). Enter·Tab·화살표·Ctrl/Alt 조합 같은 키, 다른 화면, 셸에 닿고 0.6초 안에 메아리가 없는 키(비밀번호 입력)는 묶음을 끝내고 다음 키는 다시 그리지 않는 첫 키가 된다. 그래서 그리지 않는 것: 비밀번호(메아리가 없다), 전체 화면 프로그램(vim·less·htop·셸 안의 Claude Code: 친 글자가 마지막 줄 끝에 오지 않거나 다른 줄이 바뀐다; vim·less 의 `:`·`/` 줄은 앞에 프롬프트가 없다), 붙여넣기(16자 넘게), 한 줄 입력, HTTP 길(실시간 연결이 아닐 때), 다시 잇는 동안, 글을 고르거나 위로 올려 읽는 동안. 한글은 조합이 끝난 글자만 간다(조합 중인 글자는 셸로 가지 않는다). MCP 프롬프트(`/mcp__서버__프롬프트`)는 서버를 띄워야 알 수 있어 넣지 않았다.

  - 화면은 한 번 그리고 나면 고치기만 한다: 실시간 상태가 바뀌면 연결 칸만, 알림 상태를 다시 물은 답은 알림 칸만, 고른 설정은 그 줄만 바뀐다(키보드 포커스가 그대로). 선택 칸(라디오 묶음)은 Tab 한 번에 들어가고 ←/→(↑/↓)·Home/End 로 고른다. 설정을 열면(Ctrl+, 포함, 두 칸이면 오른쪽) 포커스가 설정 페이지 자체로 간다: 테두리는 없고, 화살표·PgUp/PgDn 으로 스크롤하며 Tab 이 첫 설정으로 간다.
  - 알림 칸(`public/push.js`): 한 줄 상태(받는 중 / 꺼짐 / 거부됨 / 설치해야 함)와 될 때만 단추(알림 켜기, 또는 시험 알림·알림 끄기), 그리고 할 일 한 줄. 무엇을 보일지는 순수 함수 `pushView()` 가 기기(iPhone·Android·데스크톱)·설치 여부·권한·구독 여부로 정한다(시험 있음). 「홈 화면에 추가」 안내는 설치 안 된 iPhone 에서만, 거부됐을 때 고치는 곳도 기기마다 다르다. 허브가 아닌 호스트에서는 알림을 켤 허브 이름을 호스트 목록에서 가져온다.
  - 이 기기 저장 데이터 지우기: 보관한 대화(`herdr-hub.chats.v1`)·안 보낸 글(`drafts`)·읽음 표시(`seen`)·넘기기 안내를 지우고 다시 연다. 확인을 거치고, 설정과 알림은 건드리지 않는다.
- 화면 모드: 설정 → 화면 → 「화면 모드: 시스템 / 밝게 / 어둡게」(기본 시스템, 이 기기에 `herdr-hub.theme`). `<html data-theme>` 로 바꾼다: 어두운 값은 `style.css` 의 `--d-*` 한 곳에 있고, `:root[data-theme="dark"]` 와 시스템 다크(`:root:not([data-theme="light"])`)일 때 켜진다. `index.html` 의 짧은 스크립트가 첫 그림 전에 적용하고 `theme-color` 메타(상태 막대)·`color-scheme` 도 맞춘다. 터미널 화면은 어느 모드든 어둡다.
- 쓰다 만 글: 에이전트마다 입력 칸의 글을 이 기기의 `herdr-hub.drafts` 에 적어 둔다(치고 0.5초 뒤, 다른 데로 갈 때, 앱이 뒤로 갈 때). 탭을 닫거나 iOS 가 앱을 내려도 다시 열면 그대로 있고, 보내면 지운다. 7일 지나면 지운다. 사진은 페이지가 살아 있는 동안만 남는다. 다른 기기와는 나누지 않는다.
- 보낸 말 다시 쓰기(실제 키보드): 입력 칸이 비어 있을 때 ↑ 는 이 대화에서 보낸 말을 최근 것부터 하나씩 넣는다(대화 기록에서 읽으니 다른 기기에서 보낸 것도). ↓ 는 다시 최근 쪽으로, 끝을 넘으면 빈 칸. 불러온 글을 고치면 ↑↓ 는 다시 커서를 움직인다. 명령 제안 목록이 떠 있으면 ↑↓ 는 그 목록 것이다.
- 사진 첨부(에이전트 입력 칸만): 📎 → 사진 보관함·카메라(`accept="image/*" multiple`, 한 번에 6장까지). 입력 칸 위에 미리보기가 뜨고 ✕ 로 뺀다. 글이나 사진 중 하나만 있어도 보낼 수 있다.
  - 단추는 하나다. iPhone 은 고르는 창에 「사진 찍기」가 있고 데스크톱은 카메라를 쓸 일이 없어 바로 고르는 창을 연다. Android 는 여러 장 고르는 창에서 카메라가 빠질 수 있어 먼저 「사진 고르기 / 카메라로 찍기」를 묻는다(카메라는 `capture="environment"`).
  - 붙여넣기: 입력 칸에 이미지를 붙여 넣으면(iOS: 스크린숏 → 미리보기 누르기 → 복사(또는 복사 후 삭제) → 입력 칸 길게 눌러 붙여넣기) 같은 첨부로 들어간다(`paste` 의 `clipboardData.files`, 없으면 `items` 의 file 항목). 글은 그대로 붙는다. 이미지만 있을 때는 글자를 넣지 않는다.
  - 휴대폰에서 긴 변 2000px 까지 줄이고 JPEG 0.85 로 다시 만든다(EXIF 회전 반영, `createImageBitmap(…, {imageOrientation: 'from-image'})`, 안 되면 `<img>` 로). 2000px 안의 PNG·WebP(8MB 이하)는 그대로 보낸다. 읽을 수 없는 파일은 알림 한 줄로 거절한다.
  - 보낼 때 사진마다 에이전트가 있는 호스트에 먼저 올리고(`POST /api/uploads`, 본문은 사진 그대로 `image/jpeg|png|webp`, `X-Herdr-Hub`, 10MB 까지, 피어는 허브가 이진 그대로 넘긴다), 프롬프트는 「글 + 줄마다 절대 경로 하나」로 보낸다. 서버는 허브의 `data/uploads/<yyyymmdd-hhmmss>-<임의>.<확장자>`(폴더 0700·파일 0600, 이 사용자만; `HERDR_HUB_UPLOADS` 로 옮긴다)에 저장하고 `{path, name}` 을 돌려준다(내용이 형식과 맞아야 한다). 시작할 때와 하루에 한 번 7일 지난 파일을 지운다. `GET /api/uploads/<name>` 은 그 폴더의 그 이름 꼴 파일만 준다. 1.0.300 전에는 시스템 임시 폴더(`<임시 폴더>/herdr-hub-uploads`)에 두었다 — Linux 의 `/tmp` 는 다른 사용자도 볼 수 있어서 옮겼다. 거기 남은 사진도 찾아 주고(대화의 미리보기), 7일 뒤 같은 청소가 지운다.
  - Claude Code 2.1.317 은 프롬프트 안의 이미지 경로를 스스로 첨부한다(경로 자리에 `[Image #N]`, 기록에는 이미지 블록과 `[Image: source: <경로>]` 메타 항목). 그래서 「읽어 달라」는 안내 줄은 붙이지 않는다(desktop·server 의 haiku 로 확인: 그림 속 글자를 읽었다).
  - 대화: 보낸 말풍선에 첨부 사진을 작은 그림으로 보여 주고, 누르면 전체 화면으로 연다. 기록의 메타 항목(또는 글에 남은 경로)에서 업로드 이름을 찾아 `/api/uploads/<name>` 으로 받는다. base64 는 휴대폰으로 보내지 않는다. 업로드가 아닌 이미지(호스트에서 붙여 넣은 것)는 「이미지」 칩으로만 보인다.
